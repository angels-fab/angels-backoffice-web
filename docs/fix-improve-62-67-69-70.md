포털개선요청 **62 · 67 · 69 · 70**(전부 2026-08-11 등록, 위치 '업무현황')을 한 묶음으로 구현했다.
네 건 모두 화면에서 직접 조작해 확인했고(로그인 세션, PC 1440 · 모바일 638 양쪽), 그 과정에서

## 62 — 관련링크 아이콘을 첨부 아이콘 옆으로

링크 아이콘(OpenInNew)이 **본문 맨 아래 왼쪽**, 첨부 클립+건수가 **메타 줄 오른쪽 끝**이라
같은 성격의 두 표시가 세로로 떨어져 있었다. 링크를 메타 줄로 옮겨 **첨부 바로 왼쪽**에 붙였다.

- `TaskAccordion.tsx` — 본문의 링크 블록 제거, 메타 줄에 `링크+첨부` 묶음 Box 신설.
  `ml:'auto'`·`alignSelf:'center'`·`flexShrink:0`을 첨부 버튼에서 **묶음 Box로 올렸다**(첨부 단독일 때
  위치는 이전과 픽셀 단위로 동일 — 실측 카드 오른쪽 안쪽 15px 유지).
- 메타 줄 렌더 조건에 `|| !!link` 추가 — **첨부가 0건이어도** 링크가 설 자리가 생긴다.
  (부서·날짜·첨부가 전부 없고 링크만 있는 업무는 전에 없던 구분선 한 줄이 새로 생긴다 — 감수한 대가)
- 첨부 버튼의 onClick·aria·팝오버 로직은 **한 글자도 안 건드렸다**(선택 유지 우회로직 회귀 방지).

실측(링크+첨부 동시 배치를 DOM 복제로 모사): 두 아이콘 세로 중심 **차이 0px**, 간격 2px,
첨부는 여전히 카드 오른쪽 안쪽 15px, 줄바꿈 없음. 1440·638 폭 모두 동일.

카드 변형 중 손댈 곳은 `TaskAccordion` 하나뿐이었다 — `TaskCard.tsx`·`TaskGridAccordion.tsx`·
`TaskListDrawer.tsx`는 **어디서도 import 되지 않는 죽은 파일**이고(그 안에도 링크 아이콘 코드가 있으니
다음에 속지 말 것), 보드 카드는 링크·첨부를 원래 둘 다 표시하지 않는다.

## 67 — 링크 아이콘 호버 미리보기

새 파일 `src/pages/Work/TaskLinkButton.tsx`. 아이콘과 미리보기가 한 몸이라 62가 아이콘을 옮겨도
미리보기가 따라간다.

**★ 왜 '진짜 페이지 미리보기'가 아닌가** — 대상 사이트의 제목·대표이미지(og:image)는 CORS 때문에
브라우저가 읽을 수 없고(상대 서버가 허용 헤더를 안 준다), iframe 임베드도 대부분 X-Frame-Options로
막힌다. 서버 프록시(Supabase Edge Function) 없이는 원리상 불가. 그래서 **네트워크 요청 0건**으로,
주소 문자열에서 확실히 뽑히는 것만 보여준다:

- 서비스 추정 + MUI 아이콘 (구글 문서/스프레드시트/슬라이드/설문 · 드라이브 · Dropbox · OneDrive ·
  PDF · 그 외는 도메인+지구본)
- 도메인 (서비스 이름이 곧 도메인이면 중복 표시 안 함)
- 주소 전문 3줄까지(공유 링크는 열쇠값이 붙어 아주 길다)
- "클릭하면 새 탭에서 열립니다"

표면 규격은 캘린더 `ChipTooltip`을 그대로 따랐다(background.paper + divider 테두리 + arrow + shadow.md).
진입 300ms(`enterDelay`+`enterNextDelay` — 카드 격자를 훑을 때 안 튀게), 이탈 0ms,
`disableInteractive`(팝오버 안에 누를 것이 없다), `disableTouchListener`(모바일은 탭=바로 열기).

파비콘(google s2)은 **넣지 않았다** — 호버할 때마다 사내 문서 도메인이 구글로 전달되기 때문.
원하면 6줄로 켤 수 있다.

**현재 링크가 달린 업무는 155건 중 1건**(Dropbox 폴더)이라, 화면에서 확인되는 카드는 사실상 하나다.

## 69 — 쪽지가 다른 버튼을 눌러도 안 접히던 것

'메모'는 화면에 뜨는 붙임쪽지(StickyNote/PlainNote)다. 펼침 상태 `open`이 각 쪽지의 로컬 값인데
**바깥 클릭을 듣는 곳이 아예 없어서**, 페이지의 어떤 버튼을 눌러도 펼친 채 남았고 여러 개가 동시에
펼쳐져 쌓였다(메모를 새로 만들면 처음부터 펼쳐진 채 뜬다 — 7건이 그렇게 쌓여 있었다).

두 쪽지가 공유하는 훅 `useNoteDrag`에 `open`/`onFold`를 받아, 펼쳤을 때만 **window pointerdown(capture)**
을 건다. **이벤트를 삼키지 않는 것**이 핵심 — 그래야 클릭 한 번에 '쪽지 접기'와 '누른 버튼의 동작'이
함께 일어난다(백드롭을 깔면 2단계 클릭이 된다).

예외 셋:
- 쪽지 자신
- 쪽지가 띄운 portal UI — `.MuiModal-root, .MuiPopper-root, .MuiAutocomplete-popper`
  (상태 Menu·확인창·공유 목록. 안 빼면 상태를 고르는 순간 쪽지가 접힌다)
- **수정 중**(`editing`) — 쓰던 글이 압정 뒤로 사라지면 놀란다. 값 자체는 남지만 화면에서 없어지는 게
  더 나쁘다고 판단. "수정 중에도 접혀야 한다"면 `onFold`의 `if (!editing)` 한 줄만 빼면 된다.

부수 효과로 **한 번에 하나만 펼쳐진다**(쪽지 B를 누르면 A가 접힌다).

## 70 — 메모 수정 중 마우스 포인터

CSS `cursor`는 상속되는 속성이다. 쪽지 루트에 `cursor:'grab'`이 걸려 있고 예외가 `& input` 하나뿐인데,
수정 화면의 입력 수단은 `<input>`이 아니라 **리치 에디터(tiptap contenteditable `.ProseMirror`)**라
자기 cursor 선언이 없어 `grab`을 그대로 물려받았다 — 글을 쓰는 칸 위에서 손바닥, 누르는 동안은
`&:active` 때문에 주먹(grabbing)까지 됐다.

- 예외 셀렉터 확대: `'& input'` → `'& input, & textarea, & [contenteditable="true"]'` (요청메모·일반메모 둘 다)
  `!important` 금지 — 형광펜 모드가 인라인 style로 마커 커서를 덮는다(`richText.tsx`).
- 끌기 중 `document.body.style.cursor = 'grabbing'` 강제 + `pointerup`/`pointercancel`/언마운트에서 복구.
  `:active`만으로는 끌기 범위 끝에서 쪽지가 멈추는 순간 포인터가 쪽지 밖으로 나가 커서가 화살표로
  돌아왔다(업무 카드 드래그 3곳이 이미 쓰던 처리를 쪽지에도 맞춘 것).

실측: `.ProseMirror` cursor `grab` → **`text`**, userSelect `text`. 쪽지 루트 `grab`·접기 버튼 `pointer`·
답글칸 `text` 그대로. 끌기 중 body `grabbing`, 놓으면 빈 값.

## 곁다리로 드러난 결함 1건 — 첨부 팝업 닫는 클릭이 카드 안 버튼의 첫 클릭을 삼킴

62로 링크가 클립 버튼 **2px 옆**에 오면서 '첨부 보고 → 링크 열기'가 자연스러운 동선이 됐는데,
이때 링크가 **아무 반응 없이 한 번 무시된다**. 원인은 기존 `swallowNextClickInCard`(TaskAccordion) —
팝업을 닫는 클릭이 카드 선택을 건드리지 않게 document 캡처에서 1회 삼키는데, 그 대상에
**카드 안의 버튼·링크까지 들어가 있었다**. `preventDefault()`가 앵커의 새 탭 열기를 취소한다.

라이브 재현 확인: 팝업을 연 뒤 별(관심 업무) 클릭 → `dispatchEvent` 반환 false(취소됨), 상태 무변화.
→ 삼킴 대상에서 `CARD_SKIP`(button·a·input·textarea·contenteditable·팝업 뿌리)을 제외했다.
그리드의 선택 판정은 어차피 같은 목록을 건너뛰므로 삼킬 이유가 없었다.
수정 후 재확인: 첫 클릭에 별이 토글되고, 팝업은 닫히고, 카드 선택은 유지된다.
