# 붙임쪽지·그림이 화면을 따라다니던 것 — 문서에 붙이기 (2026-08-11, 개선요청 63)

## 증상 (사용자 신고)

> "그리기와 요청메모가 화면에 고정되지않고 따라다니는 버그 해결필요" (개선요청 63)
> "스크롤 하면 메모가 따라다녀요 ㅠㅠ" (일반메모 n23, 박세리)

표의 어느 행 옆을 가리키려고 쪽지를 놓아도, 스크롤하면 쪽지가 화면에 붙어 함께 내려와
가리키던 지점을 잃었다.

## 원인

레이어가 `position: fixed` 였다. 이 한계는 코드에 이미 적혀 있었다 —
`src/api/improve.ts` MemoStroke 주석 "레이어가 position:fixed 라 **스크롤은 따라가지 않는다**".

## 조치 — 레이어를 뷰포트가 아니라 **문서**에 매단다

### 1. 기준 사각형을 MainLayout 셸 상자로

`MainLayout.tsx` 의 셸 상자(사이드바+콘텐츠를 감싸는 flex Box)에 `position: relative` 를 주고,
`<StickyMemoLayer />` 를 그 안으로 옮겼다. 이 상자는 **상단바 바로 아래에서 문서 끝까지**를 덮으므로
레이어는 `top: 0` 만으로 원하는 사각형을 얻는다.

`#root { position: relative }`(전역 CSS)로도 되지만, 그러면 `top: 53` 매직넘버가 남고 공용 파일
`index.css` 를 건드려야 한다. 셸 상자 쪽이 실측상 정확히 같은 사각형이다.

> ⚠ 이 상자에 `transform`·`filter`·`contain` 을 걸면 안쪽 `position: fixed`(그리기 도구막대)가
> 이 상자에 갇힌다. 주석으로 남겨 뒀다.

**실측(1440×900, /work)**: `position: absolute`, `layer.clientHeight = 2229 = 문서높이 2282 − 53`,
스크롤 400 → 쪽지가 정확히 400 함께 이동, **문서 높이 변화 없음**, 가로 스크롤바 없음.
9개 경로(`/ notice calendar equipment links settings events improve work`) 전수에서
`layerH = docH − 53` 이고 항상 한 화면 이상, 가로 넘침 0.

### 2. z 순서 — 쪽지를 내리는 대신 **상단바를 올렸다**

쪽지가 문서를 따라 위로 올라가면 sticky 상단바를 덮어 메뉴·검색을 가린다.

조사 단계의 1차 안은 `z.stickyMemo` 를 90 → 40 으로 낮추는 것이었는데 **그러면 안 된다**:
레이어 루트가 `z-index + positioned` 라 **쌓임 맥락을 만들어서**, 그 안에 든 그리기 도구막대(z 91)가
밖으로 못 나간다. 레이어를 40으로 내리면 도구막대도 40으로 함께 가라앉아 업무 하단 액션바(60)에 가린다.

그래서 `z.topbar` 를 50 → **95** 로 올렸다(사용처는 `TopBar.tsx` 한 곳). 결과 순서:
`sticky 30 < bottomNav 55 < bottomBar 60 < stickyMemo 90 < topbar 95 < sidenav 100`.
하단 바들은 상단바와 겹칠 일이 없어 영향 없다.

**실측**: 스크롤 60에서 쪽지 세 개가 모두 상단바에 가려짐(`elementFromPoint` 히트 = 상단바).

### 3. 끌기 경계를 문서 기준으로

`dragBounds` 의 `minY: -TOPBAR_H` → `minY: 0`. 상단바 위로 올리던 규칙(2026-08-05 요청)은 **폐기**했다 —
문서에 붙은 뒤로 그 띠는 스크롤 0이면 상단바가 덮고 스크롤을 내리면 화면 밖이라, 어느 경우에도
보이지 않는 자리가 됐다. `TOPBAR_H` 상수는 사용처가 0이 되어 삭제(`noUnusedLocals`).

`maxY` 는 수식 그대로인데 `layer.clientHeight` 가 문서 높이가 되면서 **문서 전체가 이동 범위**가 됐다.

> ⚠ 이제 clamp 가 유일한 방어선이다. 범위 밖 쪽지는 fixed 때와 달리 **문서에 스크롤바를 만든다**.

### 4. 새 쪽지의 기본 자리 — "지금 보는 화면"에

`slotPx` 의 세로 기준이 상수 8이었다. 문서에 붙은 뒤로는 스크롤을 내린 채 만든 쪽지가
**문서 맨 위**(= 보이지 않는 곳)에 생긴다.

기준을 **상단바 아래 모서리**(`header` rect.bottom, sticky라 늘 화면의 콘텐츠 시작선)로 바꿨다.
처음엔 메모 버튼 rect 를 썼는데 버튼 바닥이 42라 맨 위에서 값이 8 → −3 으로 어긋났다(실측).

**실측**: 스크롤 0 · 800 양쪽에서 새 쪽지 자리 = 화면 y 61 (상단바 53 + 8). 예전 값과 동일.

### 5. 끄는 도중 휠을 굴렸을 때

레이어가 문서에 붙어 있어, 쥔 채 스크롤하면 레이어 원점이 함께 움직여 쪽지가 손에서 미끄러진다.
누른 순간의 스크롤(`kx`·`ky`)을 기억해 이동량에 더한다.

**'끈 것' 판정에도 스크롤을 넣었다** — 안 넣으면 손가락이 제자리라 '제자리 클릭'으로 처리돼,
휠로 옮긴 자리가 저장되지 않고 원래 자리로 되돌아간다(실측으로 발견해 수정).

**실측**: 쥔 채 200 스크롤 → 문서좌표 +200, 화면상 커서 밑 그대로, 손을 떼면 그 자리에 저장(639→839).
그냥 톡 누르면 예전처럼 펼침/접힘 토글.

### 6. 되당김을 문서 높이 변화에도

레이어 높이 = 문서 높이가 됐으므로, 목록이 늦게 도착하거나 필터·펼침으로 문서가 늘고 줄면
되당김 기준도 바뀐다. `window.resize` 만 보면 첫 페인트(데이터 로드 전 짧은 문서) 때 당겨진 자리에 굳는다.
→ 레이어에 `ResizeObserver` 를 걸었다. (쪽지는 절대배치라 레이어 높이에 기여하지 않아 되먹임 없음)

## 저장 좌표 — **키 그대로, 마이그레이션 없음, DB 쓰기 0**

`memo.pos2` 를 그대로 쓴다. 단위(px)도 원점(본문 칸 좌상단)도 그대로고 세로에 스크롤 항 하나가
더해질 뿐이다.

조회로 확인한 근거:
- `page_drawings` **0행**, `improvements.drawing` **0건** — 가장 위험하다던 공유 그림 데이터가 없다.
- 살아 있는 좌표는 7개(2명)뿐이고 **5개가 y ≤ 40**(상단 고정) — 문서 기준으로도 같은 자리.
- 저장된 y 범위 −41~914. 옛 `dragBounds` 가 세로를 **한 화면 안**으로 묶어 놨으므로, 재해석해도
  전부 "문서 첫 화면 안"에 떨어진다. 화면 밖으로 사라지는 경우는 구조적으로 불가능.
- 경로가 바뀔 때마다 `window.scrollTo(0, 0)`(MainLayout) → 대부분 스크롤 0에서 놓았다.
  실제로 63·66·67·68·69·70 의 y가 33~37로 같고 x만 슬롯 간격으로 늘어서 있다(= 맨 위 한 줄).

2026-08-05 선례([fix-memo-pin-anchor.md](fix-memo-pin-anchor.md))가 키를 바꾼 이유는 단위(%→px)와
원점이 **둘 다** 바뀌어 옛 값이 수학적으로 무의미했기 때문이다. 이번은 다르다.
보정 마이그레이션은 **불가능** — 놓을 당시의 `scrollY` 를 저장한 적이 없다.

**실측 확인**: 변경 후 살아 있는 5개 쪽지의 `offsetLeft/offsetTop` 이 DB 저장값과 정확히 일치
(162,36) (207,37) (293,33) (1054,639) (979,23) — 클램프도 이동도 없었다.
